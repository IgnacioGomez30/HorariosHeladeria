# Encargo inicial para Codex

Texto listo para usar después de extraer el repositorio. El primer encargo autorizado por este texto es **F1**.

> Actuá como responsable de ingeniería de este proyecto. Revisá la rama y el estado de Git, leé AGENTS.md, README.md y docs/00_INDEX.md. Para F1 leé también los requisitos trazables, el modelo de dominio, los modelos de datos y tiempo, el plan de pruebas, el registro de decisiones y el backlog. Consultá el contrato del motor para conservar compatibilidad futura.
>
> Identificá contradicciones que afecten esta fase. Si se pueden resolver mediante una decisión reversible consistente con lo documentado, asentala y avanzá. Para una regla particular desconocida, preservá el estado pendiente y usá fixtures sintéticos.
>
> Ejecutá B01–B03 de la fase 1, en incrementos pequeños. Prepará estructura modular, entorno reproducible y dependencias de dominio y prueba justificadas. Implementá identidad, fecha operativa, intervalos reales, múltiples bloques por jornada, duración, presencia, descanso y reglas básicas con vigencia, patrones y disponibilidad. Representá por separado los cupos de franco fijo y rotativo adicional. Registrá el comando real de instalación y ejecutá las pruebas correspondientes a cada incremento.
>
> Verificá expresamente que lunes 19:00–martes 01:00 y martes 18:00–miércoles 00:00 representan 360 minutos operativos cada uno y un descanso real de 17 horas. Sumá un caso de cambio de semana/mes, otro con bloques partidos y uno con dos personas superpuestas. Verificá que una indisponibilidad civil del martes alcance la madrugada de la jornada anterior. Usá la zona del local, precisión de minuto y fechas explícitas.
>
> Conservá los resultados en el repositorio, respetando el trabajo previo. El alcance de esta iteración termina con F1 verificada. Quedan para sus fases la GUI utilizable, la base de producción, CP-SAT, la generación y reparación, el instalador y el piloto.
>
> En el cierre informá qué se implementó, archivos modificados, pruebas y resultados reales, problemas detectados, decisiones pendientes y siguiente incremento recomendado. Identificá cualquier parte que siga sin verificar.

**Punto de control del solicitante.** Revisar los resultados concretos de F1 antes de comenzar [F2 · circuito manual](13_IMPLEMENTATION_PLAN.md). El encargado podrá evaluar las decisiones de interacción con el [prototipo](prototipos/horarios.html) en paralelo, sin usar datos reales.
